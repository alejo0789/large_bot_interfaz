# TikTok Business Messaging OAuth setup

## TikTok developer app

1. Enable the TikTok Accounts permission and the Business Messaging access needed by the app.
2. Use the **TikTok account holder authorization URL** and **TikTok account holder redirect URLs** section. The separate Advertiser authorization URL is not used for this direct-message account flow.
3. Set the TikTok account holder redirect URL to exactly:

   `https://<backend-domain>/api/tiktok/oauth/callback`

4. Copy the account holder authorization URL from TikTok My Apps after configuring the redirect URL and permissions. Do not use a link that still redirects to `webchat.siagenda.com/api/tiktok/callback`; the backend callback is the URL above.

The redirect must be a public HTTPS address in production. TikTok redirects the account owner back with an authorization code. The backend exchanges it immediately at `/open_api/v1.3/tt_user/oauth2/token/`; the code is single-use and short-lived.

## Backend environment

Set these variables in `backend/.env` locally and in the backend service's Railway variables:

- `TIKTOK_APP_ID`: app ID from TikTok My Apps.
- `TIKTOK_APP_SECRET`: app secret from TikTok My Apps. Keep it server-side.
- `TIKTOK_ACCOUNT_AUTHORIZATION_URL`: account holder authorization URL generated by TikTok.
- `TIKTOK_REDIRECT_URI`: the exact callback URL registered above.
- `TIKTOK_WEBHOOK_CALLBACK_URL`: public HTTPS endpoint for Business Messaging events, for example `https://<backend-domain>/webhook/tiktok`.
- `TIKTOK_TOKEN_ENCRYPTION_KEY`: random 32-byte key, encoded as Base64 or 64 hexadecimal characters. Keep this stable; changing it makes stored tokens unreadable.

## Business Messaging webhook

The app webhook endpoint verifies TikTok's `TikTok-Signature` header, resolves the authorized account to its tenant, and stores supported inbound text messages idempotently. It responds over HTTPS at `/webhook/tiktok`.

After the callback code is deployed and `TIKTOK_APP_SECRET` is configured, register the app-level `DIRECT_MESSAGE` subscription by running from the `backend` directory:

```sh
node scripts/subscribe_tiktok_webhook.js
```

The script sends the app ID and secret to TikTok from the backend process and prints only TikTok's response metadata. The callback URL defaults to the backend origin from `TIKTOK_REDIRECT_URI`; set `TIKTOK_WEBHOOK_CALLBACK_URL` only if the webhook is hosted elsewhere.

Generate an encryption key locally with:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

## CRM API

- `POST /api/tiktok/oauth/start`: authenticated tenant administrator; requires the tenant header used by the CRM, such as `x-sede-slug`. Returns `{ authorizationUrl }` for the frontend to open.
- `GET /api/tiktok/oauth/callback`: public TikTok callback. Validates the one-time state, exchanges the code server-side, and encrypts the access and refresh tokens in the master database.
- `GET /api/tiktok/oauth/status`: authenticated tenant administrator; returns connection status and granted scopes without returning credentials.

Tokens are stored per tenant. Access tokens are refreshed server-side when they are near expiry. TikTok message sending uses the linked tenant's token and the returned `open_id` as `business_id`.

The current prototype page remains simulated. It does not invoke these endpoints until a real Connect UI is wired to them.
